# Somnix development guidance

- Read the design proposal before changing language semantics.
- Distinguish planned capabilities from implemented behavior.
- Keep changes small and document design tradeoffs.
- Add correctness checks appropriate to implemented features; do not report unrun tests.
- Verify optimization claims with reproducible measurements and reference results.
- Never commit credentials, personal diagnostics, or unrelated learning journals.
- Do not invent working build commands while the repository remains a scaffold.
